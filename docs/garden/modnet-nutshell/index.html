MODNet in a nutshell

An interactive explainer for MODNet — the Materials Optimal Descriptor Network. The pipeline in execution order: descriptors, mutual information, feature selection, a small network, joint learning, and the genetic algorithm that tunes it.

0 · Materials ML is a small-data game

Most materials datasets have hundreds to thousands of samples, not millions. The models that win at 60 000 samples are not the models that win at 500. Pick a property and compare mean absolute error as the training set grows.

Data: measured points are verbatim from De Breuck, Hautier, Rignanese, npj Comput. Mater. 7, 83 (2021), Table I. Lines between and beyond those points are a log-log interpolation, not measured results. The paper reports only one training size for the refractive-index dataset, so it is not shown as a curve.

  • MODNet — the full pipeline: feature selection (FRR) inside the fold, then the small shared network.
  • all features — the same network, but every descriptor; no selection. This isolates the value of selection.
  • ridge — a linear model on the selected features. A cheap sanity check, not a competitor.
  • mean baseline — always predicts the training-set mean. Any useful model must beat this.

Real run: MODNet, all-features, ridge and mean baselines on matbench_dielectric, six training sizes × 3 seeds, fixed 800-sample test set. Feature selection is redone inside every training fold.

1 · Featurization: a material becomes a vector

MODNet does not learn from raw structures. It computes hundreds of standard descriptors — elemental statistics, oxidation states, bonding, density, symmetry — then lets feature selection decide which ones matter. Composition-only mode works without a crystal structure; structure mode adds the geometric features.

Feature space: every material gets the same – composition descriptors; adding the structure block makes – more, – in total. The count is identical for every material — the interesting part is which descriptors deviate.

What to look for. Oxides separate from non-oxides on electronegativity and ion-property descriptors; multi-element samples sit apart on stoichiometry and element-fraction features; an extreme cell means that descriptor is far from the six-material mean. This is the same matrix the selector sees — before any target is involved.

2 · Normalized mutual information

Feature selection needs a number for “how much does this feature tell me about the target?”. Correlation is the obvious choice, but it only sees straight lines and is sensitive to outliers. Mutual information asks a more general question: how much does knowing X reduce the uncertainty about Y? It sees any dependence — linear, quadratic, periodic.

Mutual information is the average reduction in uncertainty:

\[ \mathrm{MI}(X,Y) = \sum_{x,y} p(x,y)\,\log\frac{p(x,y)}{p(x)\,p(y)} \]

Entropy measures the uncertainty of one variable:

\[ H(X) = -\sum_x p(x)\log p(x) \]

MODNet normalizes MI by the average entropy, so the result is bounded and comparable across features:

\[ \mathrm{NMI}(X,Y) = \frac{\mathrm{MI}(X,Y)}{\big(H(X)+H(Y)\big)/2} \]

Values near 0 mean “knowing X tells you nothing about Y”; values near 1 mean “X determines Y”. In materials data, useful features often sit around 0.01–0.10 — small numbers, but far above noise.

In independent mode the slider only spreads the points; the variables stay unrelated, so NMI stays at zero — a scale change is not a dependence.

3 · Feature selection: relevance minus redundancy

The heart of MODNet. Greedy forward selection: pick the feature with the highest NMI to the target, then repeatedly pick the feature with the best trade-off between relevance and redundancy with what is already selected. The score is Eq. 2 of the paper.

At each step, every remaining candidate gets a score that rewards relevance and punishes redundancy with what is already selected:

\[ \mathrm{RR}(f) = \frac{\mathrm{NMI}(f,y)}{\left(\max_{s\in S}\mathrm{NMI}(f,s)\right)^{p}+c} \]

\[ p = \max\!\left(0.1,\; 4.5 - n^{0.4}\right), \qquad c = 10^{-6}n^{3} \]

where n is the number of features already selected. The next feature is the one with the largest RR — equivalently, the largest of the per-row minima in the plot below.

    4 · The network is deliberately small

    “Deliberately small” is the design choice, not an accident. The descriptors already encode physics, chemistry and geometry; the network's job is only to combine them. At a few hundred samples, every extra weight is another parameter to fit from too little data, so MODNet spends its capacity budget on features and selection instead of depth. The default architecture has four blocks and roughly ten thousand weights — thousands, not millions. A graph network, by contrast, must learn the representation from raw structures and needs orders of magnitude more data to do it.

    • Shared encoder — one block of dense layers that every target sees. It turns the selected descriptors into an all-round material vector.
    • Group block — one per family of related targets (e.g. thermodynamic properties): a more specialised representation, still shared inside the group.
    • Property block — narrows further toward one property.
    • Output head — one neuron per regression target (or one softmax per class).

    Default: num_neurons=([64],[32],[16],[16]), n_feat=64, ReLU, batch normalization only when there is more than one target. With 64 inputs that is about 6–7k weights; with 200 inputs, about 15k. The exact count is printed in the code map.

    5 · Joint learning: related targets regularize each other

    Joint learning trains one network on several targets at once: a shared trunk, then one head per target. It only helps when the targets actually share structure — then the trunk sees more signal than any single target provides and the extra heads act as regularizers. My first attempt used formation energy and band gap; those are weakly related, so that was a bad example. The demo below uses the case where joint learning should work: two noisy measurements of the same latent property.

    Synthetic demonstration: two targets are independent noisy views of the same latent function (noise σ = 0.35); 8 seeds per training size; identical MLP capacity (one hidden layer, 16 units). Joint = one network with two outputs; single = one network per target. This is not a MODNet result — it is the mechanism MODNet exploits.

    What it shows. From 40 samples upward the joint model wins: the shared hidden layer averages the two noise realisations. At 20 samples it loses — there is not enough data to fit the shared representation. Joint learning is not free accuracy; it is a bet that the targets share structure. In the paper the related targets were vibrational properties at different temperatures, with a ~8% MAE gain on S(305 K).

    6 · The genetic algorithm

    The least-documented part. Instead of one grid search, MODNet evolves a population of hyperparameter sets: each individual has a genome (learning rate, batch size, feature count, layer width, scaling, imputation), is scored by nested validation, and the best individuals are selected, crossed over, and mutated. Elitism keeps the best; early stopping ends a stagnant run; refit turns the winner into an ensemble.

    Mechanically: each generation scores every individual by the mean validation MAE over the inner folds. Parents are drawn with probability proportional to 1/loss5, so good individuals are strongly favoured without excluding the rest. Crossover takes a random half of each parent's genes; mutation perturbs one or more genes. The best two individuals survive unchanged (elitism). If the best loss does not improve for four generations, the run stops; the winner is refit on the full training set, optionally as a bootstrap ensemble.

    Real FitGenetic run: population 10, 5 generations, nested 3-fold validation, 800 training materials. Lower is better.

    7 · The pipeline end to end

    Composition or structure → descriptors → NMI → relevance–redundancy ranking → a small feedforward network → joint heads → GA over hyperparameters and nested validation. The bet is not a bigger model; it is better use of limited data.

    Honest limits. MODNet is descriptor-based, not a graph model. On very large datasets, graph networks win. Its accuracy depends on the featurizer preset and on the version of matminer behind it. And the current API still makes you build a MODData object — which is exactly what modnet.pt, the PyTorch rewrite, is meant to remove.
